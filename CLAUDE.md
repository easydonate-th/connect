# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Turborepo is 2.11.7, which may differ from training data. Before changing `turbo.json` or Turborepo commands, read `node_modules/turbo/docs/README.md` and the relevant pages under `node_modules/turbo/docs/`. `turbo.json` sets `agentGuidance: false`, so turbo does not generate an `AGENTS.md`.

## Overview

EasyDonate Connect: a desktop companion app that connects to an EasyDonate alert widget over WebSocket and forwards donation events to VRChat via OSC/MIDI and to VTube Studio, which throws an item at the model.

Bun monorepo managed with Turborepo (`bun@1.4.3`, workspaces `apps/*` and `packages/*`):

- `apps/desktop` (`@ezdn/desktop`) — Electrobun desktop app (Bun main process + React 19 webview) for Windows x64, macOS arm64 and Linux x64.
- `apps/unity` — Unity/VRChat world project. Only the `app.easydonate.sdk` VPM package (`Packages/`) is tracked (see `apps/unity/.gitignore`). Its example prefabs live inside it in `Examples/`, with their own `EasyDonate.SDK.Examples` asmdef and U# assembly asset, so both VCC and the `.unitypackage` ship them; `legacyFolders` in its `package.json` makes VCC delete `Assets/EasyDonateSDK`, where SDK 1.0.0's separate examples package put them. `vpm/` holds the VPM listing: `source.json` and a Scriban-templated `Website/`, which the `listing` job of `.github/workflows/release.yml` renders with `vrchat-community/package-list-action` after each release and deploys to GitHub Pages (`https://easydonate-th.github.io/connect/index.json`). VCC downloads release zips without auth, so the listing only works while the repo is public.
- `packages/` — not created yet (the workspace glob is reserved).
- `docs/` — user-facing setup guides per integration (VRChat, VTube Studio, Warudo WIP), linked from `README.md`.

## Commands

Root (run from repo root):

- `bun install` — install deps (`prepare` installs lefthook. If JS, TS, JSON or CSS files are staged, its pre-commit job runs `bun run fix` and stages the fixes again.)
- `bun run dev` — `turbo run dev` across workspaces.
- `bun run build` — `turbo run build`.
- `bun run lint` — `oxlint .`
- `bun run fmt` — `oxfmt .`
- `bun run fix` (`ultracite fix`) / `bunx ultracite check` — format + lint via Ultracite preset. `oxfmt.config.ts` ignores `.claude/**` so third-party skill docs are never reformatted.

`apps/desktop`:

- `bun run dev` — `electrobun prepare` + `vite build` + `electrobun dev --watch` (rebuilds bundled view on change).
- `bun run hmr` — runs only the Vite dev server on port 5173; start the app with `bun run start` in another terminal, and the main process (dev channel) detects the server and loads the webview from `http://localhost:5173` for HMR.
- `bun run start` — same as `dev` without `--watch`.
- `bun run build` / `bun run build:canary` — production builds (`--env=stable` / `--env=canary`).

Release: bump `app.version` in `apps/desktop/electrobun.config.ts` and/or `version` in `apps/unity/Packages/app.easydonate.sdk/package.json`, merge to `main`, then run `gh workflow run release.yml`. It makes a release tagged and titled `Release-<DDMMYYYY>-<N>` (Asia/Bangkok date; `N` is one more than the highest count that day, where an old tag without a count counts as 1; runs queue so two can't take the same tag) whose notes list both versions and link each desktop installer by its release download URL, with the desktop installers (`win-x64-…-Setup.zip`, `macos-arm64-….dmg` and `linux-x64-…-Setup.tar.gz`, each built on its own runner by the `desktop` job's matrix, since Electrobun builds only for its host; the macOS job sets `ELECTROBUN_DEVELOPER_ID` to `-`, which turns on `build.mac.codesign` and makes Electrobun sign the app ad hoc, since there is no Apple Developer ID; macOS calls an unsigned download damaged, but offers Open Anyway in Privacy & Security for an ad-hoc one) and the updater's `stable-<os>-<arch>-update.json` and `.tar.zst` bundle (but not its `.patch` from the previous release's bundle, which the build makes by fetching the previous release from `release.baseUrl`) and the SDK `.unitypackage` (checkout uses LFS for the examples' audio and font). The SDK package zip is attached only if no earlier release has that SDK version, because the listing job adds every release zip with a root `package.json` (the desktop installers have none) and would otherwise list the version twice; the `listing` job then rebuilds the VPM listing and redeploys Pages. `release.baseUrl` is `https://nozomi.easydonate.app/connect`, the `connect` bucket of a MinIO server behind Cloudflare. The app reads it anonymously by path. The `release` job creates the release as a draft and then uploads the updater's files to the bucket with the AWS CLI. It uploads the `.patch` files first, then the `.tar.zst` bundles, then `update.json`, so a manifest never names a missing file. The upload uses the `S3_ACCESS_KEY` and `S3_SECRET_KEY` secrets, path-style addressing and `Cache-Control: no-cache`. The job skips the upload for a prerelease, so the app updates from non-prereleases only. Then it publishes the release. The bucket keeps every patch, so an app several releases behind can patch its way up. Apps 1.6.0 to 1.6.2 use `https://github.com/easydonate-th/connect/releases/latest/download` as `baseUrl`, so the release still carries `update.json` and the bundle. Those apps find no patch on GitHub, download the full bundle and then update from the bucket. Apps up to 1.5.0 have no `baseUrl` and read the desktop version from the `- EasyDonate Connect: <version>` line of the latest non-prerelease's notes, so keep that line's format if you change the notes.

There is no test runner or test suite yet (oxlint config includes the vitest preset in anticipation).

## Desktop app architecture

- **Electrobun, not Electron.** Main process runs on Bun (`mainProcess: 'bun'`) with entrypoint `src/bun/index.ts` (see `electrobun.config.ts`). `electrobun prepare` generates `.hutch/devkit` (gitignored); `vite.config.ts` pulls Electrobun aliases from it and `tsconfig.json` maps `electrobun/*` imports into it via `paths` (it does not extend the devkit tsconfig, whose `baseUrl` TS 7 rejects). Run `prepare` (any dev/build script does) before type-checking or building in a fresh checkout. Type-check with `../../node_modules/.bin/tsc --noEmit -p .` from `apps/desktop`.
- **Three source dirs:**
  - `src/bun/` — main process. `index.ts` creates the `BrowserWindow` and menu, unless `single-instance.ts` finds another instance on the same channel (a kernel32 named mutex on Windows, a `flock` on a file in `userData` through libc on macOS and Linux; a second instance would forward every donation twice), in which case it shows a message box and quits; `icon.ts` sets the window icon from `Resources/app.ico` (copied from `build.win.icon`) with user32 `WM_SETICON`, since Electrobun never sets it on Windows; `rpc.ts` implements the RPC handlers; `config.ts` caches the config in memory and persists it atomically to `Utils.paths.userData/config.json`; `libs/data-folder.ts` opens `userData` in Explorer for the Data folder button in `Settings`; `libs/update.ts` reads the app version (`Updater.localInfo.version()`), checks with Electrobun's `Updater` (which compares bundle hashes, so `checkForUpdate` also requires a newer version with `Bun.semver.order`), and `installUpdate` downloads the update and relaunches into it (the `Updater` reports failures through `updateInfo().error` and its status history rather than throwing, and is disabled on the dev channel); it logs the `Updater`'s status changes and sends the install stages (a label, plus a percent while the full bundle downloads; a patch download reports none) to the webview as `updateStage` through the sink `index.ts` sets with `setUpdateStageSink`; `libs/external.ts` opens a URL in the default browser; `libs/forward.ts` calls each enabled output that `src/shared/platform.ts` (`isOutputSupported`) says runs on `process.platform` (MIDI runs on Windows only; OSC and VTube Studio everywhere); `libs/vrc/` holds the VRChat outputs (`osc.ts`; `midi/`) and `libs/vts/` the VTube Studio one. In `libs/vrc/midi/`, `index.ts` (`sendDonationMIDI`) sends a donation in paced chunks, one donation at a time (VRChat's MIDI input throws and drops events when a frame gets more than 128); `utils.ts` documents the protocol and `encodeDonation` turns a donation into Control Change messages (JSON, one character each); `winmm.ts` has `getMIDIDevices` and `sendMIDI`, which call winmm.dll through `bun:ffi` (Windows only; ports come from loopMIDI).
  - `src/mainview/` — React 19 + Tailwind v4 + shadcn/ui webview. Vite root is `src/mainview`, output goes to `apps/desktop/dist`, which Electrobun copies into `views/mainview/` (loaded as `views://mainview/index.html` in non-HMR mode). Import alias `~/*` maps to `src/mainview/*`.
  - `src/shared/` — imported by both sides with relative paths: the zod `ConfigSchema` and the types derived from it (`config.ts`; every field has its own fallback through `withFallback` (zod's `.catch`, aliased so the promise lint rule doesn't misfire), so `ConfigSchema.parse` heals one bad value in `config.json` or an RPC payload without resetting the rest, drops unknown fields, drops invalid array entries such as custom images whose `fileName` isn't `importVTSImages`' format, and sorts and prunes throw rules, adding a default one when none are left; the main process runs it at its I/O boundary in `bun/config.ts`; `validateConfig` reuses the field schemas to report, rather than heal, each invalid field of the UI's draft, plus the rules that span fields, as messages keyed by form path) and `Donation` (`donation.ts`, mapped from the socket `DONATE` message without validating fields, since the widget's message shape is fixed), plus the `AppRPC` contract (`rpc.ts`).
- **VTube Studio output:** in `src/bun/libs/vts/`, `client.ts` (`withVTSSession`) opens a Plugin API WebSocket (Bun's global `WebSocket`) per call, authenticates and closes it; `api.ts` types each request's `data` and response by `messageType`. The plugin token lives in `token.ts`'s `Utils.paths.userData/vts-token.json`, not in `Config`, so a stale webview `saveConfig` can't overwrite it; without a valid token, `AuthenticationTokenRequest` waits up to two minutes for the user to click Allow in VTube Studio, and concurrent sessions share that one request (`allowCustomImages` does the same for the `LoadCustomImagesAsItems` permission). `throw.ts` (`sendDonationVTS`) finds the throw rule with the highest `minAmount` the donation reaches (none: it throws nothing) and throws its `count` items, each picked at random from the selected `Items` folder files and all of the user's images, or, when the rule is `custom`, from its own `items` and `images`, 150 ms apart in one session: it loads the item off-screen with `unloadWhenPluginDisconnects`, flies it with `ItemMoveRequest`, from one of the screen edges the zone's `zoneDirections` entry lists (left, right or both, picked at random), at one of the rule's `zones` (head, body, feet) picked at random, as wide as the zone's `zoneWidths` entry (pixels, centered on the model's x) and a band of the model's visible height that `outline.ts` (`getModelBounds`) reads from one `ModelOutlineEvent` frame (the session's `waitForEvent` resolves on the next event of a name; without a frame it aims at `CurrentModelRequest`'s model position), moved down by the rule's `zoneOffsets` for that zone (pixels, negative moves up, converted with the frame's `windowSize`, since item x and y span -1 to 1 over the window; without a frame, width and offset don't apply), knocks the model's head away from it with `reaction.ts` (`createHitReaction`: a damped spring, shared by the donation's items, that adds to the `FaceAngleX/Y/Z` and `FacePositionX` tracking inputs through `InjectParameterDataRequest` in `add` mode every 33 ms until it settles, scaled by `hitForce`, 0 for off, and less for body and feet hits; the session stays open until it does), drops it out of view (sending `ItemUnloadRequest` at the hit when `fadeTime` is set, so it fades while dropping) and closes the session, which unloads it. It sends a custom image's data only on its first load, then reuses the name VTube Studio returned until a load fails with 751 (VTube Studio restarted). `images.ts` imports images through `Utils.openFileDialog`, checks them against VTube Studio's custom data limits (PNG/JPG/GIF header, under 5 MB, 64-2048 px a side) and copies them to `Utils.paths.userData/vts-images` as `ezdn-<8 hex>.<ext>`, the name format VTube Studio requires; the `saveConfig` handler deletes images the saved config no longer lists. The main window enables Electrobun's `appdata://` protocol (`allowedProtocols.appData`), which serves `userData` to the webview, so `VTS/ImageThumbnail` previews images through `getVTSImageUrl`; it also exposes `config.json` and `vts-token.json` to whatever the window loads, so it must never navigate to remote pages. `connection.ts` (`testVTSConnection`) reports the VTube Studio version and loaded model for the Test connection button; `items.ts` (`getVTSItems`) lists the `Items` folder; VTube Studio reads the folder from disk for this, so the UI only scans on demand.
- **Typed RPC bridge:** `src/shared/rpc.ts` defines `AppRPC`: the `bun` side answers `getConfig`/`saveConfig`/`getMIDIDevices`/`getVTSItems`/`testVTSConnection`/`importVTSImages`/`openDataFolder`/`getAppVersion`/`getPlatform`/`checkForUpdate`/`installUpdate`/`openExternal` (the VTube Studio, import and update wrappers raise `maxRequestTime` to cover the VTube Studio approval wait, the open file dialog, the updater's 30-second wait for `update.json` and the download) and receives the fire-and-forget `donation` and `testDonation` messages (a test donation carries the form's draft config, which the handler heals with `ConfigSchema`); the webview receives `log` and `updateStage` (stored in `libs/update-stage.ts`, read with `hooks/use-update-stage.ts`). The main process implements it in `src/bun/rpc.ts`; webview wrappers live in `src/mainview/libs/rpc.ts`. To add a capability: extend `AppRPC`, implement the handler in `src/bun/rpc.ts`, add a wrapper in `libs/rpc.ts`.
- **Donation flow:** `hooks/use-widget-socket.ts` connects to `wss://socket.easydonate.app/ezdn<widget query>&ex=easyconnect` (URL built by `getSocketUrl` in `libs/utils.ts`) with `react-use-websocket` (infinite reconnect with backoff, ping/PONG heartbeat) and parses each frame with `parseDonationMessage`. Some frames (e.g. PONG) arrive JSON-encoded twice; `src/shared/socket-frame.ts` unwraps them. `hooks/use-widget-connection.ts` owns the socket URL and sends each `Donation` to the main process, which forwards it to the enabled OSC/MIDI/VTube Studio outputs using the cached config; a test donation is forwarded with the form's current values (`getValues`) instead, so it tests unsaved changes too. The socket connects when the user clicks Connect, or on launch when the saved `autoConnect` setting is on.
- **Logs:** `src/bun/logger.ts` writes to the console and pushes each entry to the webview over the `log` RPC message; the webview adds its own entries through `log` in `src/mainview/libs/logs.ts` (an in-memory store, read with `hooks/use-logs.ts`, that also records incoming socket frames (minus PONG heartbeats and TTS fields, see `libs/raw-frame.ts`) in a separate 500-line buffer for the panel's Raw log toggle). The Logs button toggles `components/LogsPanel.tsx`.
- **UI:** shadcn/ui (`components.json`, Radix base, Nova preset). Add components with `bunx shadcn@latest add <name>` from `apps/desktop`. Generated files in `components/ui/` are excluded from oxlint. `App.tsx` suspends on the initial config load (`use(initialConfigPromise)` plus `Suspense` in `main.tsx`) and passes it to `hooks/use-config-form.ts`, whose react-hook-form form holds the editable draft and is provided with `FormProvider`; components read and write it through the form context (`useController`, `useWatch`, `useFieldArray` for the throw rules, `setValue` with `shouldDirty`), and `NumberField` and `OutputCard`'s `name` cover number fields and output switches. Its resolver turns `validateConfig` into `formState.errors`, and because RHF revalidates only the changed field while most rules span fields, a `subscribe` effect revalidates the whole form on every change; `save` resets the form to what the main process stored. The `desktop-component-pattern` skill (`.claude/skills/`) sets the layout of a component's body and these form conventions. `hooks/use-midi-devices.ts` lists MIDI ports over RPC, scanned on mount and on demand; `hooks/use-vts-items.ts` lists VTube Studio items only on demand, since the first scan shows VTube Studio's approval popup; `hooks/use-vts-image-import.ts` imports the user's images, which `VTS/Throw` adds to the draft; `hooks/use-unsaved-changes-toast.tsx` keeps a non-dismissible toast with a Save button on screen while the draft differs from the saved config, except while a component calls `useHideUnsavedChangesToast(true)` (`VTS/RuleZonesDialog` while it is open, since its Save button saves through `useConfigSave` from `hooks/use-config-form.ts` and then closes it; it ignores clicks outside; `VTS/ThrowRules` keeps the last rule dialog mounted after it closes, so Radix can play its exit animation). `App.tsx` composes `WidgetConnection` (widget URL, auto connect, Connect/Test buttons), `Integrations` (it reads the main process's platform with `use(platformPromise)` from `libs/platform.ts` and passes `isSupported` from `isOutputSupported` to an output, whose `OutputCard` then shows a "Platform not supported" badge in place of its switch and fields; accordion of `VRC/OSC` and `VRC/MIDI` under VRChat and `VTS/Throw` under VTube Studio, whose items are split into a VTube Studio tab (checkbox list from Scan) and a Your images tab, followed by `VTS/ThrowRules` (the Logic list of rules: Min THB, Items to throw, a Custom image checkbox whose Choose button opens `VTS/RuleItemsDialog` to pick from both tabs, a Hit zone button that opens `VTS/RuleZonesDialog`, which also holds each zone's throw sides (`VTS/ZoneDirectionField`, Left and Right checkboxes), pixel offset and pixel width, grayed out while the zone is unchecked (`validateConfig` skips them then), and a Reset button that, after a confirm popover, puts the rule's zone settings back to `createVTSThrowRule`'s defaults in the draft, and remove, each row a `VTS/ThrowRule`; `ConfigSchema` sorts them by Min THB and prunes picks no longer in the tabs), each wrapped in `OutputCard`; its `AccordionContent` gets `h-auto`, because the generated component fixes the content's height to what Radix measured on open and would clip content that grows later), `Settings` (the app version, the Data folder button, a GitHub button and Check for updates, then Update and restart, through `hooks/use-app-update.tsx`, which toasts the result (the install toast's description is `UpdateProgress`, the stage label and a shadcn `Progress` bar) and refuses to install while the draft has unsaved changes, since the restart would drop them; links go through `openExternal` in `libs/rpc.ts`, never `<a href>`, since the window must not navigate to remote pages), and `LogsPanel`. `TestDonationButton` (in `WidgetConnection`, `VTS/ThrowRules` and `VTS/RuleZonesDialog`) sends a fake donation through the same `donation` RPC and is disabled while the socket is connected or connecting. Light theme only. The font is FCVision, the EasyDonate site's font, bundled as woff2 in `src/mainview/fonts/` (only the weights the UI uses: 400, 500, 600). The files' ascent metrics (`hhea` ascent, `OS/2` typo and win ascent) are lowered from 1120 to 880 with fonttools, so the line box centers the 700-unit capitals beside icons, as Geist did; the macOS WebKit view ignores CSS `ascent-override`, so the files carry the change. Patch any newly added weight the same way, and do not add `ascent-override` in CSS, which would lower Chromium's ascent twice.

## Code style

Enforced by oxlint/oxfmt (Ultracite presets core, react, tanstack, vitest, anti-slop) with project overrides:

- Single quotes, no semicolons, 80-col, 2-space indent, `arrowParens: 'avoid'`, sorted imports (groups separated by blank lines), sorted Tailwind classes.
- React components must be arrow functions (`react/function-component-definition`).
- Nested ternaries, `await` in loops, and warning comments are allowed.
